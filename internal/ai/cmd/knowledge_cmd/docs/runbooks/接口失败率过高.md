# 接口失败率过高

## 适用范围

适用于单个接口失败率明显升高，而同一服务的其他接口或基础资源暂时正常的场景。

## 常见现象

- 某个接口的错误率持续升高。
- 网关能够转发请求，请求也能到达应用。
- 同一服务的其他接口没有同时出现异常。
- 失败原因可能来自本服务调用异常或下游服务不可用。

## 初步判断

先按接口名称定位请求，再根据日志中的 response 和 error 判断是本服务处理失败还是下游依赖失败。

## 排查步骤

### 第一步：确认接口和时间范围

记录失败率开始升高的时间和接口名称，先查询最近一小时的日志。

### 第二步：筛选接口响应日志

使用接口名称和 `response` 关键词筛选相关日志，避免直接扫描全部服务日志。

### 第三步：分析 error

查看筛选结果中的 `error` 内容，区分以下两类方向：

- 本服务调用或参数处理异常。
- 下游服务不可用、超时或返回错误。

## 验证恢复

- 目标接口失败率恢复到正常水平。
- 新产生的 response 日志不再持续出现同类 error。
- 下游依赖恢复后，接口请求能够成功完成。

## 常见误判

- 看到网关正常就认为应用没有问题。
- 只搜 `error`，没有先用接口名和 `response` 缩小范围。
- 把所有失败都归因于下游，没有核对 error 的调用链信息。

## 升级条件

如果无法区分本服务和下游原因，应保留接口名、时间范围、response 日志和 error 内容，再升级给对应服务或下游负责人。负责人和升级时限需要由业务团队补充。
